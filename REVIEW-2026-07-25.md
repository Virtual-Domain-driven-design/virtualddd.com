# Deep review: live virtualddd.com vs. the Astro rebuild

Written 2026-07-25, at commit `6e1f04d`. Three parts, as asked:
**(1)** live-vs-new differences, **(2)** UI-design judgement on each of them plus a
look-and-feel/UX critique, **(3)** front-end code review of adaptability. Ends
with a proposal and the decisions I need from you.

Evidence: full-page screenshots of both sites at 1280 px and 390 px, a crawl of
all 20 live sitemaps (967 indexed URLs) diffed against the 314 routes the new
build emits, DOM measurements of the running dev server, and two independent
code reviews of the repo that were run separately and agree with each other.

This is the part I did not expect. The live main nav does **not** link to the

- **Papers** and **Books** — `/papers/`, `/books/`, both in the footer and on

- **Book Club** — in the live main nav, advertising an event that started

### 1.4 Page-type differences

**Home.** New adds: a live countdown to the next session, a working Bluesky
feed, "Latest stories", a 4-item organiser carousel, an "AI usage" disclosure,
a much richer footer. New drops: papers, books, the hardcoded video embed, and
"Recent Github Repositories". The live "Follow us on BlueSky or Mastadon" panel
is an empty black box and the "VIDEOS" panel is an empty white box — both
render as broken furniture today.

**Session detail.** New adds: level badge, type badge, **local-time rendering**
(live shows UTC only), an "About the host" card with photo/role/links,
real prev/next titles (live says only "PREVIOUS SESSION"), tag chips, a sidebar
with date/host/YouTube/Discord/latest. New drops nothing. The live page's
"Discussed Heuristics" section says *"No Heuristics captured in this session"*
on every session I sampled.

**Session index.** Live `/meetup-sessions/`: 8 white cards, 2 columns, left
filter rail, Load More. New: 107 sessions, 4 columns, top filter bar (search +
level + type + tags + reset), type badges, host names. Strictly better and much
denser. Live `/sessions/` is an unbranded WP archive, 5 per page, 22 pages.

**Stories.** Live `/facilitating-archdes/` is a **white-background, unbranded**
WP blog archive with a "Recent Posts" sidebar. The new one is branded and
on-message — but see §2.3, it is 19,887 px tall.

**Heuristics.** The new `/heuristics/` browsable index (search, tag filter,
type badges, counts per type, load-more, 152 items) is new capability. Live has
only a landing page plus WP archives, and its three type tiles are
`et_clickable` divs **with no `href`** — not crawlable, not keyboard-reachable.
The new site also finally *displays* the heuristic type; live never did.

**Open Space.** Live `/ddd-open-space/` shows an empty state ("No new sessions
scheduled") and omits Global Domain-Driven Day 2024 (4 of 5). New shows all 5.

## Part 2 — UI-design judgement

### 2.1 Verdict on each difference

**New is better, keep it — no further discussion needed:**
local-time rendering with a countdown; level and type badges; the "About the
host" card; titled prev/next; the browsable heuristics index; type finally
being visible on a heuristic; the top filter bar over the left filter rail; the
dense 4-column session grid; showing all 5 open spaces; the ddd-crew section;
one URL family per section; no cookie banner.

**New is better but incomplete:** the footer (richer, but "Explore" duplicates
the main nav rather than adding the *Categories* depth the old footer had —
papers, books, podcasts, videos). The home page (better in every module, but it
dropped three modules and nothing replaced them).

**Old is better, and I would bring it back:**

1. **Level shown on session cards.** The live cards print
   `Level: Intermediate` under the title. The new grid filters by level but
   never displays it. If it is worth filtering on, it is worth showing.
2. **A visible "Categories" column in the footer.** Not the specific list, but
   the *idea*: the old footer was a site map, the new one is a nav duplicate.
3. **Papers and books.** Small, curated, on-brand for a learning community, and
   currently vanishing without a decision.

**Old was different, and I think the rebuild's call is right anyway:** dropping
Book Club and Podcasts from the main nav (both broken/stale live), replacing
the video wall with the Bluesky feed, and dropping the WP taxonomy archives in
favour of client-side filters — *provided* §1.1 gets a redirect decision.

### 2.2 Branding and look-and-feel

The brand itself is strong and unusually well-preserved. Near-black canvas,
electric cyan `#16bde8` and hot pink `#ec5fa6`, Rajdhani for headings against
Poppins for body, the neon wireframe cube logo. It reads "engineering
community, slightly underground" and it does not look like a WordPress theme.
The rebuild honours it: the extracted tokens are real and used for roughly 95 %
of values, and the identity survives at 390 px.

Three brand-level problems, all fixable:

1. **The dark/light card split is unexplained.** Sessions, stories, open spaces
   and ddd-crew use dark cards on the dark canvas. Heuristics uses **white**
   cards. Both look fine alone; together they read as two different sites. Pick
   one rule and write it down — my recommendation: dark cards are the default,
   white is reserved for the heuristic "index card" metaphor *and applied
   consistently everywhere a heuristic appears* (it currently isn't — the
   heuristic cards inside session and story pages are dark).
2. **Text on photographic backgrounds fails contrast.** The three heuristic type
   tiles (home, `/heuristics/`, `/ddd-heuristics/`) put small body copy over
   busy Kandinsky-style paintings with no scrim, and the About page puts a cyan
   "About us" over a light painting. This is the one place the visual identity
   actively fights legibility. A 55–70 % dark scrim, or a solid panel, fixes it
   without touching the palette.
3. **The gradient placeholder is arbitrary.** Nine files draw a
   `linear-gradient(135deg, …)` for missing images, some primary→accent, some
   accent→primary. On a grid it looks like a rendering fault rather than a
   choice.

### 2.3 Does the information architecture work for engineers and product owners?

Mostly yes. The site's job is: *find a session to attend, watch one you missed,
read the thinking behind it.* The rebuild serves the first two well. Where it
falls down:

1. **The stories index is 19,887 px tall** — 24 full-width single-column cards,
   each with a hero image and excerpt. It is the worst page on the new site.
   A three-up grid at ~4,000 px would show all 24 without a single scroll
   marathon. The live site (4,081 px) genuinely wins here, by paginating.
2. **The session index has filters *and* a Load More.** Filtering hides cards
   client-side; Load More reveals them in batches. The two interact badly: a
   filter can appear to return nothing because the matches are in a batch not
   yet revealed. Verify or restructure (filter should reset the batch window).
3. **Four competing CTAs in the home hero.** RSVP (pink), Join Google Meet
   (cyan), Watch livestream (outline), More info (outline) — shown ten days
   before the event, when only two of them are actionable. One primary action,
   the rest demoted or time-gated.
4. **There is no search.** Two hundred and eighty content pages and no way to
   search across them; each index has its own local filter instead. Pagefind is
   already in the plan (Phase 7) — it is more valuable here than it looks,
   because heuristics/sessions/stories cross-reference each other constantly.
5. **The heuristic graph is still under-exploited.** Heuristics relate to
   sessions, stories and to each other. From a session you can reach its
   heuristics; from a heuristic you get "discussed in". That is the strongest
   argument for the whole migration and it is currently one hop deep.
6. **Nothing tells a first-time visitor what happens next.** The live site has
   the same problem. There is no "next session is on X, here's how to join, it
   is free" strip that survives past the hero, and no newsletter or calendar
   subscription anywhere on either site. For a meetup community that is a
   surprising gap: an `.ics` feed and a "add to calendar" link on every upcoming
   session would cost very little.

### 2.4 My own design questions (these need your answers, not mine)

1. **Who is the home page for — the returning member or the first-time
   visitor?** It currently serves the returning member (latest sessions, latest
   stories, Bluesky). If it should convert strangers, the mission statement and
   "how to take part" need to outrank the feeds.
2. **Is the session archive a *catalogue* or a *library*?** 107 items shown as
   equal cards is a catalogue. A library would surface *why* an old session
   still matters — by topic, by heuristic, by speaker. Which one are you
   building?
3. **What is the primary conversion?** Discord join, RSVP, or YouTube
   subscribe? Three different answers appear on three different pages. Pick one
   per page type and let the others be secondary.
4. **Should heuristics be the site's front door?** It is the only content type
   nobody else publishes this way, it is 152 items deep, and it is buried fifth
   in the nav.
5. **Do you want speaker/organiser pages?** You have the data, the live site
   has 8 indexed team pages that are about to 404, and people search names.
6. **Should past sessions keep their RSVP furniture?** Today the layout is
   identical for upcoming and past; only the buttons change.
7. **Do you want analytics at all?** WordPress had a cookie banner because it
   tracked. The new site tracks nothing — which is a defensible, on-brand
   choice, but it means you will not be able to see whether cutover cost you
   traffic. Decide before, not after.

## Part 3 — Front-end code review

Two independent reviews plus my own DOM testing. They agree on the diagnosis:
**the content pipeline and the design tokens are good; the CSS and page layer
is copy-paste accretion.**

### 3.2 The structural problem: 87 % of the CSS is per-page

909 lines of scoped `<style>` against 131 lines of shared CSS. The consequences
are measurable:

| Pattern | Copies | Drift already visible |
|---|---:|---|
| Card implementations | **16–19** across 13–16 files | hover rules identical; gradients randomly reversed |
| `.eyebrow` + `::before` | **14** | `letter-spacing` `0.12em` ×10, `0.1em` ×2 |
| Two-column detail grid | 4 | byte-identical, incl. `top: 5.5rem` |
| Prev/next nav | 4 | 3 byte-identical |
| Prose body block | 4–5 | 3 share `max-width: 42rem; font-size: 1.05rem` verbatim |
| Carousel CSS + JS | 4 | same hardcoded `+ 16` gap |
| Filter bar CSS + JS | 3 | and all three carry bug #3 |
| Heuristic type metadata | 5 | **already drifted into 3 different descriptions** |
| `youtubeEmbed()` | 3 | one copy **is missing the `/embed/` fallback** |
| `shortDate` | 6 | 3 different format objects |

There is **no `src/lib` and no `src/utils`**. 57 raw hex colours and 54 `rgba()`
literals sit outside the token system, and there are 30 media queries across
**11 different breakpoints** (620/640/700/720/800/820/860/900/960/980).

### 3.3 Is it adaptable? Can Claude Code change it safely?

Honest answer: **it is easy to *add* to and expensive to *change*.**

| Task | Files today | After extraction |
|---|---:|---:|
| "Restyle all cards" | 13–16 | 1 |
| "Add a speakers section" | 9 files, ~370–450 lines, ~120–300 of it copy-paste | ~60 lines |
| "Add a new collection" | 5 minimum | 3 |
| "Fix the mobile filter overflow" | 3 | 1 |

The failure mode is specific and worth naming, because it is the one Claude
Code will hit repeatedly: with 16 near-identical card blocks and no shared
class, a request to change "the cards" produces a change to *most* of them and
a silent divergence in the rest — exactly what already happened to `.eyebrow`,
to `youtubeEmbed()` and to the heuristic type descriptions. Nothing in the
compiler catches it. Every such request costs a full-repo grep and burns
context that should go into the actual design decision.

The Notion side has the opposite property and is genuinely well built.

### 3.4 What is good and must survive any refactor

- `src/styles/tokens.css` — real tokens, honoured ~95 % of the time.
- **Zero JS frameworks, zero emitted JS bundles**, 314 pages in ~6 s.
- Progressive enhancement done properly: every `<time>` ships server-rendered
  fallback text, filters only *hide* pre-rendered cards, and
  `global.css:82 [hidden] { display: none !important }` exists specifically to
  make that work with flex cards. This is also the right vehicle for fixing
  bug #5.
- `CONTENT_SPECS` in `sync-notion.ts:426-505` — adding a Notion field really is
  a one-line change.
- `blocksToMd` fidelity: 15 block types, **zero** `TODO block:` markers and
  **zero** expiring Notion URLs in the committed content.
- `sync-ddd-crew.ts`'s failure discipline: per-repo try/catch, prune only on a
  clean run, with comments explaining why.
- Per-collection status enums in `content.config.ts`; `reference()` on the
  heuristics graph; typed `CollectionEntry<'x'>` props on all card components;
  `youtube-nocookie` everywhere; consistent `minmax(0, 1fr)` overflow hygiene.

## Proposal — what to change before continuing the migration

Five steps. **Steps 1 and 2 are done** (see below); step 3 is the decision that
gates Phase 6.

### Step 1 — Fix the confirmed bugs ✅ done

- `--space-5` / `--space-10` added to `tokens.css`, plus `--color-ink`,
  `--color-ink-muted`, `--color-primary-ink`, `--color-accent-ink`,
  `--color-heur-value` for the values that were hardcoded.
- **Mobile overflow fixed**: `.detail > * { min-width: 0 }` and
  `min-width: 0; max-width: 100%` on filter selects, plus
  `overflow-wrap: anywhere` on links in prose. Verified by re-scanning 80
  detail pages at 390 px: **15 overflowing → 0**.
- Dangling relations: the heuristics lookup is now built from **Published**
  rows only, drops are collected and reported per entry
  (`slug → property: title`), and `--strict` exits non-zero for CI.
- `sync-notion.ts` now **prunes** files it did not produce (never on a
  `--limit` run), and **writes only after every page has rendered**, so a
  mid-run failure cannot leave `src/content/` half-updated.
- Notion API calls go through a pacer (~2.9 req/s) with 429/5xx retry and
  `Retry-After` support.
- Bluesky fetch has a 5 s timeout and warns instead of failing silently.
- All 7 glued text-before-link cases fixed. (One remains inside *generated*
  content — a missing space in the Notion source of one heuristic.)
- `undefined/orig-organisers.png` deleted.
- `scripts/prune-dist.mjs` runs after every build: **dist 46 MB → 24 MB**
  (167 unreferenced originals, 22.5 MB). Verified all 306 referenced assets
  still resolve.
- `astro check`: **107 hints → 0** (`astro/zod` import, `z.url()`, unused
  identifiers).
- `npm run sync` now exists — CLAUDE.md's manual-fallback invariant had no
  actual command behind it.

### Step 2 — Extract the shared layer ✅ done

`src/styles/patterns.css` + `src/lib/{dates,embeds,excerpt,collections,heuristics}.ts`
+ `TeaserCard`, `Carousel`, `PrevNext`, `HeuristicDetail`, `HeuristicTypePage`.

- Card implementations **16 → 1** (`TeaserCard`; `SessionCard`/`StoryCard` are
  now 20-line wrappers).
- `.eyebrow` **14 → 1**; prev/next **4 → 1**; detail grid **4 → 1**; prose
  body **5 → 2** (article + README); carousel CSS+JS **4 → 1**; filter CSS
  **3 → 1**; heuristic type metadata **5 → 1** (the three drifted
  descriptions are now one).
- `youtubeEmbed` **3 → 1** (with the `/embed/` fallback all three now share),
  `shortDate` **6 → 1**, `excerpt` **2 → 1**.
- The six `any`s in `heuristics/[slug].astro` are gone: the route is now a
  typed switch over two components.
- The footer's "Explore" list is generated from the nav array — it was a
  second, drifting copy.
- Every change verified against a functional smoke test (filters, type
  banners, `?type=` deep links, reset, load-more, carousels, countdown,
  local-time swap) and screenshot comparison at 1280 px and 390 px.

**One finding from the report was wrong**: the session index's filter *does*
reset the load-more window (`apply(true)` in `sessions/index.astro`), so
filtering cannot hide matches behind an unrevealed batch. Nothing to fix.

### Step 3 — URL fate of the 674 missing URLs ✅ done

Decided 2026-07-25 and implemented. `public/.htaccess` is generated by
`scripts/build-redirects.mjs` (174 rules) and verified by
`scripts/check-redirects.mjs`, which replays every rule against the Phase 1
crawl:

```
checked 967 indexed URLs against 174 rules
  served by a page : 295
  redirected (301) : 411
  gone (410)       : 261
all indexed URLs are handled.
```

| Group | Decision |
|---|---|
| 289 session/heuristic/story tag archives | **301** to the filtered index (`/sessions/?tag=x`). All 289 legacy slugs match a tag in the current content; `src/lib/filter-url.ts` pre-selects it, and an unknown tag falls back to the full archive rather than an empty page |
| 9 open-space tag archives | 301 to `/open-space/` — five items, no filter UI |
| 237 `videos_tag` + 18 category/author archives | **410** |
| 95 video URLs whose slug matches a session | **301** to that session — same video, plus the write-up |
| 441 remaining videos | **410**; imported third-party conference talks (KanDDDinsky, DDD Taiwan). Inventory committed so the section can return at the same URLs |
